# DraftMD 产品设计规格

- **状态：** 已完成需求访谈，待用户审阅书面规格
- **日期：** 2026-08-31
- **产品：** DraftMD（暂定名称）
- **平台：** macOS 13+，Apple Silicon 与 Intel Universal 构建
- **发行方式：** 开源免费
- **基础项目：** 基于 ColaMD Fork，遵守并保留其 MIT License 与版权声明

> **DraftMD 是一款面向产品和技术团队的开源 macOS AI Markdown 编辑器，让用户与 LLM 在本地文档工作区中共同编写和维护需求、设计与项目文档。**

## 1. 背景与产品机会

产品需求、技术设计、会议记录和项目说明通常存放在多份 Markdown 文档中。一次决策发生变化后，用户必须手动找到并更新所有相关文件，容易产生遗漏、矛盾和过期内容。

普通 AI 写作工具通常只处理当前文本，缺少跨文档理解与可靠的文件修改能力；通用编程 Agent 则拥有 DraftMD 场景不需要的 Shell、代码执行和全项目权限，增加了复杂度与风险。

DraftMD 位于两者之间：

1. 首先是一款可靠、克制的 Markdown 编辑器；
2. 同时内置一个只服务于当前 Markdown 文件夹的文档 Agent；
3. Agent 按需读取多份文档，并可直接创建、修改或重命名 Markdown；
4. 所有任务变更都可检查、追溯并整次撤销。

## 2. 目标用户与核心场景

### 2.1 目标用户

首版优先服务：

- 产品经理；
- 软件工程师与架构师；
- 技术负责人；
- 设计师与项目负责人；
- 需要共同维护产品、技术和项目文档的个人或小型团队成员。

DraftMD 本身不提供多人实时协作；“团队”场景指用户维护团队共享的本地或 Git 管理的 Markdown 文档。

### 2.2 核心文档类型

- 产品需求文档；
- 技术设计与架构说明；
- 项目 README 与开发约定；
- 会议记录与决策日志；
- 验收清单、发布计划和复盘文档。

### 2.3 核心价值

1. **写得更快：** 起草、扩写、润色和结构调整。
2. **保持一致：** 将新决策同步到需求、设计和会议记录。
3. **减少遗漏：** 按需检索相关文档并更新受影响内容。
4. **用户可控：** 权限限制在当前 Markdown 文件夹，变更可检查、可撤销。
5. **开放且本地优先：** 开源免费、用户自带模型、数据保存在本机。

## 4. 产品原则

### 4.1 编辑器优先

不配置 LLM 时，DraftMD 仍必须是一款完整、可靠的 Markdown 编辑器。模型初始化、连接失败或任务运行均不得阻塞普通编辑。

### 4.2 内容优先

延续 ColaMD 的克制界面：不增加常驻工具栏、状态栏或复杂 IDE 面板。默认界面由轻量文件列表、居中编辑区和折叠任务坞组成。

### 4.3 本地优先

Markdown、会话、快照和设置保存在本机。DraftMD 不提供账号、云同步或自营模型额度。仅在用户调用远程 LLM 时，将任务所需的文档内容发送给对应服务。

### 4.4 最小权限

Agent 只能操作当前工作区内允许的 Markdown 文件。Provider 或模型能力的变化不能扩大本地权限边界。

### 4.5 变更真实、可恢复

界面状态必须与磁盘结果一致。任何产生文件变更的任务都要生成最终变更集；失败、停止和部分完成不能隐藏已发生的写入。

## 5. 核心用户体验

### 5.1 首次启动

首次启动流程：

1. 根据 macOS 系统语言选择简体中文或英文，可手动切换；
2. 用户打开一个包含 Markdown 文档的文件夹；
3. 用户可配置 LLM，也可跳过并直接使用编辑器；
4. 应用简要说明 Agent 权限：仅当前文件夹、仅 Markdown、普通修改直接写入、删除需确认、任务可整体撤销。

未配置 LLM 时，底部任务坞显示“配置模型后开始协作”，但不阻止编辑。

### 5.2 主界面

主界面包含：

- **左侧轻量文件列表：** 当前工作区中的 Markdown 文件和目录；
- **中央编辑器：** 最大内容宽度约 780px，保持 ColaMD 的居中与留白；
- **底部任务坞：** 默认折叠为单行输入，开始对话或执行任务时向上展开。

任务坞特性：

- 顶部边缘可拖动调整高度；
- 用户可随时收起，收起不停止任务；
- 支持快捷键显示、隐藏和聚焦；
- 展开后显示会话、消息、工具活动、任务状态、停止操作和变更结果；
- 正文宽度不会因任务坞展开而改变。

### 5.3 编辑能力

MVP 包含：

- Milkdown 所见即所得编辑；
- Markdown 源码模式；
- 自动保存与保存状态；
- 外部文件改动实时同步；
- 当前文档搜索；
- 文档大纲；
- 本地图片渲染；
- 表格、任务列表、代码块；
- Mermaid 与 LaTeX；
- 浅色和深色主题；
- HTML 与 PDF 导出。

暂缓 Word 导出、长图导出、多窗口和自定义主题导入。

### 5.4 发起 AI 任务

折叠状态显示：

- 会话入口；
- 当前模型；
- 单行输入框；
- 发送按钮。

发送后任务坞展开，展示：

- 当前会话；
- 用户与模型消息；
- Agent 正在读取、搜索或修改的文件；
- 准备、运行、等待确认、完成或失败状态；
- 停止任务按钮。

任务完成后展示：

- 本次任务摘要；
- 创建、修改、重命名和删除的文件列表；
- 按文件查看的最终 Diff；
- “撤销本次任务”；
- 继续追问输入框。

### 5.5 选区协作

用户在所见即所得或源码模式中选择文本并按 AI 快捷键：

1. 任务坞展开；
2. 输入框上方显示引用卡片，包括文件、标题路径和内容摘要；
3. 当前选区成为显式上下文；
4. Agent 可按需读取其他 Markdown；
5. 修改直接写回目标位置；
6. 完成后展示局部 Diff。

选区定位优先使用“文件 + 标题路径 + 前后文本锚点 + 内容摘要”，而不是只依赖行号。若执行前目标内容发生变化，写入被拒绝并提示重新引用。

### 5.6 跨文档任务示例

- “把今天会议记录里的决策同步到产品需求和技术设计。”
- “检查需求文档与技术设计是否存在矛盾，并直接修正。”
- “根据产品需求创建一份技术设计初稿。”
- “找出所有仍标记为待确认的事项，整理成一份新文档。”
- “把这次范围调整同步到当前文件夹中的相关文档。”

### 5.7 会话管理

每个工作区拥有独立会话集合：

- 新建、继续、重命名和删除会话；
- 首条任务可自动生成标题；
- 记录对话、模型切换点、工具活动和任务变更；
- 重新打开工作区后继续会话；
- 切换工作区时同步切换会话集合；
- 会话数据不写入用户工作区，不参与 Git 提交。

## 6. LLM 配置

### 6.1 Provider 类型

#### Anthropic 原生接口

- API Key；
- 模型名称；
- 可选自定义 Base URL；
- 流式响应；
- 原生工具调用。

#### OpenAI 原生接口

- API Key；
- 模型名称；
- 可选自定义 Base URL；
- 流式响应；
- 原生工具调用。

#### OpenAI-compatible 接口

- 配置显示名称；
- Base URL；
- API Key，可为空；
- 模型名称；
- 自定义请求头；
- 超时时间；
- 流式输出开关；
- 工具调用能力开关。

#### 本地模型预设

- Ollama；
- LM Studio；
- 自定义本地 OpenAI-compatible 服务。

预设只负责填充常见默认地址，不负责下载、启动或管理模型。

### 6.2 多套配置

每套配置记录：

- 显示名称；
- Provider 类型；
- Endpoint；
- 模型名称；
- 非敏感请求参数；
- 能力检测结果；
- 最近连接测试结果。

用户可设置全局默认配置，在新建会话时选择配置，并在会话内切换模型。切换点进入会话记录；历史不会自动重发给旧模型，但新模型会收到当前任务所需的有效上下文。

### 6.3 凭据与隐私

- API Key 保存在 macOS Keychain；
- 敏感自定义 Header 值同样保存在 Keychain；
- SQLite 只保存凭据引用；
- 日志不记录密钥、完整请求头、完整 Prompt、完整回复或完整文档正文；
- 删除配置时询问是否同时删除 Keychain 凭据；
- 首次使用远程配置时明确说明，任务按需读取的文档内容会发送给对应模型服务。

网络默认：

- 远程 Endpoint 默认要求 HTTPS；
- `http://` 默认允许 localhost、127.0.0.1 和局域网地址；
- 其他 HTTP Endpoint 需用户显式允许并确认风险。

### 6.4 连接测试与能力等级

保存配置前测试：

1. Endpoint 可达性；
2. 凭据有效性；
3. 模型可调用性；
4. 流式输出；
5. 结构化工具调用；
6. DraftMD 工具参数结构兼容性。

能力分级：

- **文档 Agent：** 通过工具调用测试，可执行完整文件任务；
- **仅聊天：** 可生成文本，但不能可靠调用工具，只能讨论当前文档或选区，不能直接操作文件。

## 7. Agent 工具与上下文

### 7.1 工具集

Agent 只获得受约束的 Markdown 工具：

- `list_markdown_files`：列出相对路径、大小和更新时间；
- `search_markdown`：搜索关键词，返回文件、标题路径和上下文片段；
- `read_markdown`：读取文件或标题章节；
- `create_markdown`：创建文件，存在冲突时拒绝覆盖；
- `edit_markdown`：执行基于原文和版本校验的受约束编辑；
- `rename_markdown`：在工作区内重命名或移动 Markdown，目标冲突时停止；
- `delete_markdown`：只有 UI 确认后才执行。

不提供通用文件系统、Shell、代码执行、网页、URL 或 MCP 工具。

### 7.2 基础上下文

每次任务默认包含：

- DraftMD 的权限和行为规则；
- 当前工作区 Markdown 文件清单；
- 当前打开的文件；
- 当前选区或引用；
- 当前会话有效历史；
- 可用工具定义。

其他文件由 Agent 按需搜索和读取。DraftMD 不在每次请求中发送整个工作区。

### 7.3 用户可见活动

任务坞展示用户可验证的活动，例如：

```text
读取 产品需求.md / 验收标准
搜索 “离线模式” · 3 处匹配
修改 技术设计.md
创建 发布检查清单.md
```

不展示或伪造模型内部推理；只展示文件操作、等待原因和简短状态。

### 7.4 执行限制

每次任务包含：

- 最大工具调用次数；
- 最大连续运行时间；
- 用户随时停止；
- 重复调用检测；
- 同一路径连续无效编辑检测；
- 上下文不足时停止或缩小读取范围，不静默截断；
- 只有通过适配层结构验证的工具请求可以执行。

## 8. 系统架构

### 8.1 总体分层

```text
Renderer
  编辑器 · 文件列表 · AI 任务坞 · Diff · 设置
       │ 受限 IPC
Preload
  仅暴露经过验证的最小能力
       │
Electron Main
  Workspace · Session · Agent · Provider · Credential · Snapshot
       ├── 本地 Markdown 文件
       └── 远程 LLM API 或本地模型服务
```

### 8.2 Editor Core

沿用 ColaMD 的 Milkdown 编辑能力，负责：

- 所见即所得与源码模式；
- 文档渲染、选区和文本锚点；
- 自动保存；
- 外部文件同步；
- 当前编辑状态与 Agent 修改的协调。

Editor Core 不直接调用 LLM，也不访问会话数据库。

### 8.3 Workspace Service

- 所有路径解析为工作区根目录下的相对路径；
- 拒绝 `../`、绝对路径和符号链接逃逸；
- 只允许 `.md`、`.markdown`；
- 写入使用临时文件与原子替换；
- 每次读写维护文件版本标识；
- 文件监听器区分用户、Agent 和外部写入；
- 首版 Agent 不读取、生成、移动或删除图片文件。

### 8.4 Agent Runtime

任务生命周期：

```text
创建任务基线
→ 组装基础上下文
→ 请求模型
→ 验证工具调用
→ 执行文件工具
→ 返回工具结果
→ 继续循环或结束
→ 生成最终变更集
```

Agent Runtime 只依赖统一的 `ProviderAdapter`，不直接依赖具体 SDK。

### 8.5 Provider Adapters

首版包含：

- `AnthropicAdapter`；
- `OpenAIAdapter`；
- `OpenAICompatibleAdapter`。

统一事件模型：

- 流式文本；
- 结构化工具调用；
- Token 使用；
- 停止原因；
- 标准化错误；
- 模型能力信息。

### 8.6 Session Store

使用本地 SQLite，支持：

- 工作区、会话和消息关系；
- 模型切换点；
- 任务、工具活动和变更元数据；
- 中断恢复；
- Schema 迁移；
- 删除会话或工作区记录而不影响 Markdown 文件。

数据库损坏不得阻止用户直接打开和编辑 Markdown；应用应提供重建或隔离损坏数据库的恢复路径。

### 8.7 Credential Store

统一凭据接口，底层使用 macOS Keychain。Renderer 不接触明文凭据；Provider 请求在主进程或隔离服务中构造。

### 8.8 Snapshot & Diff Service

本地数据建议布局：

```text
~/Library/Application Support/DraftMD/
├── draftmd.sqlite
├── snapshots/
│   └── <workspace-id>/<task-id>/
├── logs/
└── settings.json
```

每次任务开始时创建任务基线。任务结束后由基线和最终磁盘状态生成 Diff。

撤销规则：

- 文件无后续变化：直接恢复；
- 文件有后续变化：尝试三方合并；
- 无法安全合并：展示冲突，不静默覆盖；
- 新建文件无后续修改：删除；有后续修改：要求确认；
- 重命名：检查原路径和新路径状态后恢复；
- 经确认删除的文件：从任务基线恢复。

## 9. 并发与一致性

DraftMD 同时面对三种写入：

1. 用户编辑；
2. 内置 Agent；
3. 外部工具。

统一规则：

- 文件操作携带读取时的版本标识；
- 写入前重新验证版本；
- 版本不一致时拒绝写入并返回冲突；
- Agent 可重新读取后再次尝试；
- 禁止“最后写入者获胜”式静默覆盖；
- 更新非当前文件时刷新文件状态；
- 更新当前文件时尽量保留光标、选区和滚动；
- 当前文档有未保存内容时，先完成自动保存，再重新校验版本。

## 10. 任务状态与错误处理

### 10.1 状态机

每个任务处于以下一种状态：

- 准备中；
- 运行中；
- 等待确认；
- 已完成；
- 部分完成；
- 已停止；
- 失败；
- 已撤销；
- 撤销冲突。

状态必须反映真实磁盘结果：存在文件变更时不能只显示“失败”；只有完成既定目标时才能显示“已完成”。

### 10.2 模型配置错误

- 不启动文件任务；
- 显示具体原因；
- 提供“打开模型设置”和“重新测试”。

### 10.3 限流、余额不足或服务中断

- 保留已完成修改；
- 标记“部分完成”；
- 展示受影响文件和 Diff；
- 允许继续、撤销或重新评估后重试；
- 不重复执行已完成工具操作。

### 10.4 上下文不足

- 不静默截断；
- 说明无法纳入的内容；
- 优先缩小到标题章节或相关片段；
- 无法安全完成时停止。

### 10.5 并发变化

- 拒绝冲突写入；
- Agent 可重新读取并生成新编辑；
- 多次冲突后停止修改该文件并写入最终摘要。

### 10.6 无效工具调用

- 未通过结构验证的调用不执行；
- 将错误返回模型一次以允许修正；
- 重复相同错误时自动停止；
- 普通文本绝不解析为文件操作。

### 10.7 应用异常退出

下次启动不自动继续调用模型。应用展示“上次任务意外中断”，列出已发生的变更，并允许查看 Diff、保留或撤销。

### 10.8 删除确认

确认界面显示：

- 相对路径；
- Agent 的删除理由；
- 文件是否在任务开始后变化；
- 取消与确认删除。

多个删除项可以集中展示，但必须允许逐项取消。关闭应用时，未确认删除按取消处理。

### 10.9 停止与重试

停止后：

- 取消尚未完成的模型请求；
- 阻止后续工具调用；
- 正在执行的原子写入完成或安全回滚；
- 已完成修改保留并生成 Diff；
- 状态为“部分完成”或“已停止”。

提供：

- **继续任务：** 保留现有变更，让模型基于当前工作区重新评估；
- **撤销后重试：** 恢复任务基线后从头执行。

不得机械重放旧工具调用序列。

## 11. 安全与隐私边界

Electron 要求：

- `contextIsolation: true`；
- `nodeIntegration: false`；
- Renderer 不持有 API Key；
- Renderer 不直接访问文件系统；
- IPC 参数进行运行时校验；
- 外部链接使用系统浏览器；
- 模型返回的 Markdown 不作为可执行 HTML；
- Mermaid 继续在隔离环境中渲染；
- 自定义 Endpoint 不能扩大文件权限。

Workspace Service 必须防止：

- 绝对路径访问；
- `../` 路径穿越；
- 符号链接逃逸；
- 大小写与规范化差异导致的边界绕过；
- 非 Markdown 扩展名伪装；
- 工具输入中的未验证路径。

## 12. 日志与诊断

默认日志只记录：

- 时间；
- 模块；
- 任务状态；
- Provider 类型；
- 标准化错误代码；
- 文件相对路径和操作类型；
- 请求耗时和 Token 用量。

默认不记录：

- API Key 和敏感 Header；
- 完整 Prompt；
- 完整模型回复；
- 完整文档正文；
- 用户绝对路径。

导出诊断包前自动二次脱敏，并先向用户列出将包含的信息。

## 15. 核心验收场景

### 15.1 会议决策同步

工作区包含 `产品需求.md`、`技术设计.md`、`会议记录.md`。用户要求将已确认的离线模式决策同步到需求和设计。

必须满足：

- Agent 按需读取；
- 只修改相关章节；
- 活动记录准确；
- 摘要与 Diff 准确；
- 一键撤销后恢复任务前状态。

### 15.2 创建设计初稿

用户要求根据需求创建技术设计。

必须满足：

- 读取需求；
- 创建有效 Markdown；
- 文件名冲突不覆盖；
- 新文件即时出现；
- 撤销安全删除；
- 新文件有后续手改时，撤销必须确认或报告冲突。

### 15.3 选区补全

用户引用“错误处理”章节，要求参考其他文档补全异常场景。

必须满足：

- 识别文件和标题路径；
- 按需搜索其他文档；
- 只修改引用章节；
- 引用变化时拒绝写入；
- 展示局部 Diff。

### 15.4 删除保护

用户要求删除旧版技术方案。

必须满足：

- Agent 可提出删除；
- 删除暂停等待确认；
- 显示路径与理由；
- 取消后文件不变；
- 确认后删除；
- 撤销可恢复。

### 15.5 能力不足的模型

本地模型能聊天但不能可靠调用工具。

必须满足：

- 标记“仅聊天”；
- 可讨论当前文档或选区；
- 不承诺直接文件修改；
- 普通文本不会被当作工具调用。

## 16. 非功能要求

### 16.1 性能

- 编辑器交互不等待 LLM 初始化；
- AI 运行时输入和滚动保持流畅；
- 文件列表与搜索可流畅处理 1,000 个 Markdown 文件；
- 单个 5 MB Markdown 文件可打开和编辑；复杂渲染可以按需降级；
- Diff 与快照不阻塞 Renderer；
- Provider SDK 延迟加载，不显著拖慢冷启动。

### 16.2 可访问性

- 关键操作支持键盘；
- 图标按钮有可访问名称和 Tooltip；
- Diff 不只依赖红绿颜色；
- 中英文关键文案不截断；
- 状态由文字和图形共同表达；
- 遵循 macOS“减少动态效果”。

### 16.3 数据可靠性

- 每个 AI 任务有可用基线；
- 每次文件写入有版本校验；
- 崩溃后能说明已发生的磁盘变化；
- 撤销不静默覆盖后续人工编辑；
- 会话数据库异常不阻止普通 Markdown 编辑。

## 17. MVP 完成定义

只有以下条件同时满足，DraftMD 首版才算完成：

1. 不配置模型时仍是可靠的 Markdown 编辑器；
2. Anthropic、OpenAI 和至少一个本地 OpenAI-compatible 服务完成验证；
3. Agent 能可靠执行跨文件读取、修改和创建；
4. 删除确认、版本冲突和停止任务不会造成静默数据丢失；
5. 每个产生变更的任务都有最终 Diff；
6. 无后续冲突时可准确整次撤销；
7. 工作区和会话可在重启后恢复；
8. 中英文核心流程完整；
9. Apple Silicon 与 Intel Universal 构建通过验证；
10. 安全测试证明 Agent 无法逃逸当前 Markdown 工作区。

## 18. 发布前未决事项

这些事项不阻塞产品规格，但必须在正式开发或发布阶段解决：

1. **名称核验：** DraftMD 存在一个旧的同名开源组件，且市场上有名为 MDraft 的 macOS Markdown 产品。发布前需完成商标、域名、GitHub 与 App Store 检索。
2. **新增代码许可证：** 当前意向是开源免费；在创建 DraftMD 仓库时明确采用 MIT 或其他具体开源许可证。无另行决定时，建议沿用 MIT，以便与 ColaMD 基础代码保持清晰兼容。
3. **快捷键细节：** 在实施计划中根据现有 ColaMD 快捷键和 macOS 冲突表确定 AI 任务坞、选区引用、源码模式等具体按键。
4. **Provider 具体模型默认值：** 不在产品规格中写死；应用应允许用户输入或从 Provider 查询模型，并以能力测试为准。
5. **任务运行上限：** 最大调用次数和最大运行时间的具体默认值应通过实现阶段测试确定，并允许高级设置调整。

## 19. 规格范围结论

本规格定义的是一个可独立实施的 DraftMD MVP：它复用 ColaMD 的成熟编辑器基础，新增本地持久会话、多 Provider 配置、受限文档 Agent、任务级 Diff 与撤销，并把权限限制在当前 Markdown 工作区。

Web、MCP、Shell、知识库、云同步和跨平台均被明确排除，因此该 MVP 虽然涉及多个子系统，但仍围绕一条单一产品闭环，可以进入后续实施规划。
